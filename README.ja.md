# iap2loc

[中文](README.md) · [English](README.en.md) · **日本語**

**Windows 10/11 x64**、**macOS Apple Silicon (arm64) / Intel (x64)**、**Android 8.0+** に
対応したクロスプラットフォームの iOS 位置情報変更クライアントです。

iAP2 プロトコルを通じて iOS デバイスへ位置情報（NMEA）を送信し、デバイス管理、
地図上での位置指定、パラメーター設定を行えるローカル Web コンソールを提供します。
iOS は複数の位置情報ソースを統合するため、接続に成功してもシステムの位置情報が
必ず変更されるとは限りません。  
>⚠️ macOS は現在実験的なサポートのみで、動作は保証されません

## ダウンロードとシステム要件

対応するビルドは
[Releases](https://github.com/D1ngtalk/iap2loc/releases) から入手するか、
[ソースからビルド](#ソースからのビルドと-ci)してください。

| プラットフォーム    | ビルド成果物                       | 要件                                                       |
|---------------------|-----------------------------------|------------------------------------------------------------|
| Windows 10/11 x64   | `iap2loc-windows-x64.exe`         | ペアリング済み Bluetooth デバイス、MFi 認証情報            |
| Windows 10/11 x64   | `iap2loc-windows-x64-bundled.exe` | ペアリング済み Bluetooth デバイス（認証情報ファイル不要）  |
| macOS Apple Silicon | `iap2loc-macos-arm64.dmg`         | macOS の Bluetooth 権限、ペアリング済みデバイス、MFi 認証情報 |
| macOS Intel         | `iap2loc-macos-x64.dmg`           | macOS の Bluetooth 権限、ペアリング済みデバイス、MFi 認証情報 |
| Android 8.0+        | `iap2loc-android.apk`             | Bluetooth 搭載の Android スマートフォン、MFi 認証情報。アプリ内に初回ガイドあり（[README-Android.md](README-Android.md)、中国語） |

リリースビルドは自己完結型で、通常は別途 .NET をインストールする必要はありません。
ソースからのビルドには **.NET 10 SDK** が必要です。macOS ビルドは ad-hoc 署名であり、
**Apple Developer ID による公証は行われていません**。ビルドの提供元を信頼できる場合のみ
システム設定から許可し、Gatekeeper をグローバルに無効化しないでください。

## クイックスタート

1.  **インストール**：Windows ではダウンロードした EXE を実行します。macOS では
    お使いのアーキテクチャの DMG を開き、アプリを Applications にドラッグして、
    **システム設定 → プライバシーとセキュリティ → Bluetooth** でアクセスを許可します。

2.  **ペアリング**：オペレーティングシステムの Bluetooth 設定で iPhone を
    ペアリングします。

3.  **コンソールを開く**：アプリケーションを起動し、同じマシンで
    <http://127.0.0.1:8737/> にアクセスします。同一 LAN 内のスマートフォンや
    別のコンピューターからは `http://<ホスト IP>:8737/` で開けます。

4.  **デバイスを接続する**：**デバイス** で iOS デバイスを追加し、接続ステータスが
    **認証済み** になることを確認します。

5.  **座標を設定する**：地図上で位置を選択するか、[パスモード](#パスモード)を
    使用します。パラメーターを調整して **変更を適用** をクリックします。
    デバイスの位置情報が最終的に変更されるかどうかは、iOS の位置情報統合に
    依存します。

6.  **デバイス側で位置情報ソースを切り替える**：

    1.  **Wi-Fi、モバイルデータ通信、位置情報サービスをオフにします。** 10 秒待ってから
        位置情報サービスを再びオンにします——このとき Wi-Fi はまだオンにしないでください。
    2.  **マップを開き**、位置情報ソースが iAP2 に切り替わったことを確認します。
        青い点が、デバイスの実際の位置ではなく設定した座標に表示されるはずです。
    3.  **Wi-Fi をオンにし、モバイルデータ通信はオフのままにします。** 位置情報が
        安定するのを待ってから、モバイルデータ通信を再びオンにします。

    > **これらの手順を繰り返しても位置情報を変更できない場合：** 場合によっては、
    > 他の位置情報ソースのキャッシュデータの影響で、マップがおおよその範囲を示す円と
    > 「現在地を特定できません」というメッセージを表示することがあります。その場合は
    > Wi-Fi、モバイルデータ通信、位置情報サービスをオフにしてデバイスを再起動します。
    > 再起動後、Bluetooth で接続して座標を再設定し、手順 2 から再開してください。

## 機能

- **Android アプリ**：同じ Web コンソール・設定形式・全機能を単体アプリで提供し、初回ガイド
  （権限、MFi インポート、ペアリング、接続テスト、iPhone 側の手順）、バックグラウンド送信用の
  フォアグラウンドサービス、オフライン地図ライブラリを備えます。[README-Android.md](README-Android.md) を参照。
- **クロスプラットフォーム転送**：Windows の Bluetooth、macOS の
  IOBluetooth/SDP/RFCOMM。
- **Web コンソール**：デバイス一覧、接続セッション、単点モードとパスモード、
  リアルタイム調整、複数デバイス管理。レイアウトは狭い画面に適応し、コンソール
  ログは詳細設定でパネル下部に展開できます。
- **地図と座標**：OpenStreetMap WGS-84 / 高德 GCJ-02、自動座標変換、保存した位置。
- **単点モード**：地図上で直接座標を選択するか、目標の緯度と経度を入力します。
- **パスモード**：地図上でポリラインを作成するか、GPX ファイルをインポートします。
  `<time>` を含む GPX は記録されたペースで再生され、それ以外の場合は目標が設定した
  速度で移動し、ループも可能です。
- **ランダム化**：メートル単位の位置オフセット（0 で無効）、ランダムな精度、
  ランダムな高度。後者 2 つはそれぞれ独自の範囲を持ちます。値は適用時に一度決定され、
  その後は固定されます。
- **NMEA**：GGA と RMC。測位品質（0〜8）、衛星数（0〜99）、速度、方位、高度、精度。
- **送信間隔**：既定は 250 ms、最小は 10 ms。デバイスが `0xFFFA` で指定した購読間隔が
  `--rate` より優先されます。
- **アクセサリーのアイデンティティ**：`iap2loc.json` に設定と保存した位置が格納されます。
  既定では、アクセサリー名とシリアル番号は起動ごとにローテーションされ、Bluetooth
  アドレスは設定で管理できます。手動でのアイデンティティおよびアドレスの変更も
  サポートされています。これは実際の Bluetooth ハードウェアアドレスを変更するものでも、
  iOS の位置情報統合の回避を保証するものでもない点に注意してください。
- **大きな距離の変更**：100 m を超える移動の場合、プログラムは遷移フレームに速度と方位を
  含めることができます。これは iOS が位置情報を受け入れることを保証するものではありません。

## パスモード

単一の点を保持する代わりに目標をポリラインに沿って移動させるには、コンソール上部で
**パス** に切り替えます。モードの変更とパスの編集は **変更を適用** したあとにのみ
反映されます。

- **地図での指定**：地図を順にクリックしてポリラインを作成します。番号付きマーカーを
  ドラッグして移動し、右クリックで 1 点を削除し、必要に応じて元に戻すかクリアします。
- **GPX インポート**：`trkpt`、`rtept`、`wpt` をサポートします。5000 点を超える
  トラックはダウンサンプリングされます。
- **タイムスタンプ再生**：すべての点が `<time>` を持つ場合、記録されたペースが
  再現され——速い区間・遅い区間・停止も記録どおりに保たれ——NMEA の速度は現在の
  セグメントの速度になります。タイムスタンプが欠けているか時刻が減少している場合は、
  一定速度にフォールバックします。
- **一定速度**：設定した km/h で移動します。ループを有効にすると終点で最初から
  やり直します。
- **進捗**：適用された線には点の数、長さ、移動距離が表示されます。タイムスタンプ付きの
  パスでは総所要時間も表示され、速度入力は無効になります。
- **点の追加でタイムスタンプが消去される**：インポートした GPX の地図をクリックすると
  一定速度にフォールバックし、一部が時刻付きで一部が一定速度というデータを避けます。

## コマンドライン

Windows では実行ファイルのあるディレクトリから、macOS ではアプリの
`Contents/MacOS` ディレクトリから実行します（実際のファイル名を使用してください）：

```bash
./iap2loc devices
./iap2loc serve --port 8737
./iap2loc run --transport bt --mac AA:BB:CC:DD:EE:FF --lat 31.2304 --lon 121.4737
./iap2loc run --transport bt --mac AA:BB:CC:DD:EE:FF --probe -v
./iap2loc run --transport tcp --host 127.0.0.1 --port 12345 --lat 31.2304 --lon 121.4737
./iap2loc inspect-identity --identity ./identity
```

| オプション                                    | 用途                                                                               |
|-----------------------------------------------|------------------------------------------------------------------------------------|
| `--lat`, `--lon`                              | 目標の緯度と経度                                                                   |
| `--alt`, `--speed`, `--bearing`, `--accuracy` | 追加の NMEA フィールド                                                             |
| `--quality`, `--satellites`                   | GGA の品質と衛星数。既定は 1 / 8                                                   |
| `--rate`                                      | 既定の間隔（ミリ秒）。デバイスの購読値が優先されます                               |
| `--identity`                                  | MFi アイデンティティのディレクトリ                                                 |
| `--config`                                    | 設定ファイルのパス（既定はアプリケーションディレクトリの `iap2loc.json`）          |
| `--fixed-identity`, `--fixed-adapter`         | 対応するアイデンティティまたはアドレスのランダム化を無効化します                   |
| `--probe`, `-v`                               | 識別プローブのみ。詳細なプロトコルログ                                             |

`--sentences` は削除されました。送信されるのは GGA/RMC のみです。

## MFi アイデンティティとセキュリティ

MFi 認証を完了するには、**正当に取得した** アクセサリーのアイデンティティ認証情報が
必要です。このリポジトリには秘密鍵や証明書は含まれていません：

```text
identity/
├── identity.pk8       # PKCS#8 DER P-256 private key
└── certificate.p7b    # Accessory certificate chain
```

パスは `--identity ./identity` で指定します。アイデンティティがなくても、デバイスの
検出、リンク、識別のトラブルシューティングは可能ですが、MFi 認証を完了することは
できません。**鍵、証明書、設定ファイル内のシークレット、実際のデバイス情報を含む
ログを GitHub にコミットしないでください。**

## ソースからのビルドと CI

```bash
dotnet build Iap2Loc.csproj -c Release
# Windows self-contained single file
dotnet publish Iap2Loc.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -o dist
# macOS: run the repository script on a Mac with the matching architecture
bash scripts/package-macos.sh arm64 dist/iap2loc-macos-arm64.dmg
# Use x64 for an Intel Mac
# Android: needs JDK 17+ and the Android SDK, see README-Android.md
cd android && ./gradlew :core:test :app:assembleRelease
```

macOS のパッケージングには Xcode Command Line Tools（`clang`、`xcrun`）も必要です。
自動化ワークフロー：[macOS](.github/workflows/macos.yml)。これは ARM64 と Intel の
別々のランナーで DMG のビルド、マウント、スモークテストを行います。通常のプッシュと
プルリクエストでは Actions Artifacts をアップロードするのみです。2 つの DMG は、
リリースが公開されたとき、または指定したタグでワークフローを手動で再実行したときにのみ、
既存のリリースに添付されます。詳細は該当するワークフロー実行の結果を参照してください。

## トラブルシューティング

| 症状                                               | 確認すること                                                                                            |
|----------------------------------------------------|---------------------------------------------------------------------------------------------------------|
| macOS でデバイスが表示されない                     | システムの Bluetooth 権限、ペアリング状態、IOBluetooth の列挙                                            |
| デバイスは見つかるが接続できない                   | SDP が iAP2 UUID をアドバタイズしているか、RFCOMM チャンネルが利用可能かどうか                           |
| 識別が拒否される                                   | `--probe -v` を使って識別メッセージを確認する                                                            |
| 認証に失敗する                                     | 正当に取得した MFi アイデンティティファイルと証明書チェーンを確認する                                    |
| 購読は受信されるが位置情報が変わらない             | `0xFFFA`、NMEA、iOS のマルチソース位置情報統合を確認する。位置情報の上書きは保証されません               |
| LAN からコンソールにアクセスできない               | ファイアウォールがポート 8737 を許可しているか、両方のデバイスが同一サブネットにあるかどうか             |
| Actions は成功するが Releases に DMG が現れない     | 通常ブランチのビルドでなかったか確認する。リリースイベント、公開ジョブ、アセット一覧を検証する           |
